**同一份遊戲規格，交給四個 AI 模型，做出來的成品會差多少？** 這次我用 Qwen3.8-Max、DeepSeek V4.1 Flash、SWE-2 Max 和 GPT-6 Astra，實作一款 60 秒海上救援遊戲。四份作品都能開始救援；真正值得看的是資訊怎麼呈現、哪裡需要修正，以及成品如何交到玩家手上。

<!--more-->

## 四個模型，實際做出了什麼？

先看這次可核對的結果。表格以**模型**分類，執行工具另外列出，避免把平台名稱與模型能力混在一起。

| 模型 | 執行工具／設定 | 這次最明顯的差異 |
|---|---|---|
| Qwen3.8-Max | Qoder CLI | 狀態列搭配出發提示；初次執行到 25 分鐘上限時已有遊戲，後續補上檢查紀錄 |
| DeepSeek V4.1 Flash | Command Code | 畫面直接顯示分數與愛心耐久；內容生成完成，卻卡在寫檔權限 |
| SWE-2 Max | Devin CLI | 鍵盤、搖桿與暫停說明清楚列出；後續修正預警時序與碰撞保護 |
| GPT-6 Astra | Codex，xhigh | 四項救援狀態分開呈現，接人、滿載和返港都有文字回饋；屬於後續追加的對照作品 |

**目前沒有「最好玩」的冠軍。** 四份作品各通過 12 項受控規則檢查，共 48 項；這能支持特定規則運作正確，不能替玩家決定操作手感。

試玩入口讓讀者先用 A／B／C／D 選版本，玩過後再揭曉模型。**截至本文草稿完成，公開試玩與線上投票尚未上線。** 正式開放後，會在這裡補上入口與玩家票數。

## 為什麼做成「載人回港」的遊戲？

遊戲叫做**風暴前的最後一班**。海上有 12 名落水者，你要在 60 秒內送回至少 8 人，並保住救援艇。

船最多載 3 人，每多一人，速度會減少基礎速度的 8%。接到人之後必須回港，才算救援成功。因此，每趟都會遇到一個選擇：繞路接第三個人，還是先把船上的人送回去？

漂流木會扣耐久，漩渦只會減速。救回 8 人後，要撐到倒數結束；12 人全部回港則能提前成功。這些規則把路線、容量與風險連在一起，也讓比較有了具體目標：模型能否完整實作同一套決策，而不只是讓船在畫面上移動。

## 最值得記錄的，是兩種不同的卡關

**DeepSeek V4.1 Flash 遇到的是交付障礙。** Command Code 已產生完整檔案內容，但寫入被權限阻擋。我們從紀錄中原樣保存內容，沒有代改玩法。這件事會影響實際拿到成品的時間，卻不能直接算成模型寫不出遊戲。

**SWE-2 Max 則需要修正遊戲規則的時序。** 共同規格要求在第 20、40 秒加入漂流木，並提前 1.5 秒預警。初版的預警與啟用時間需要調整，碰撞後的無敵時間也做了修正。這類問題不一定能從一張截圖看出來，必須真的推進遊戲狀態才能核對。

這也是我想把成品和製作過程一起公開的原因：成功生成檔案、能啟動遊戲、符合規則，是不同的交付階段。

## 哪些條件相同，哪些條件不同？

四份作品使用相同地圖、落水者位置、速度、碰撞規則與共用圖像，第一輪也統一無聲。模型可以自行安排介面與提示，但不能改救援目標和計分。

不過，**GPT-6 Astra 是後續追加的版本**。它保留了前面整合與驗收的對話上下文，也沒有套用前三版初次 CLI 的 25 分鐘限制。這些差異會影響結果，必須一起交代。

另外，四個模型透過不同工具執行，權限、等待與操作流程也各不相同。這篇比較的是**這次交出的作品與製作過程**，不能用一次結果推論通用模型排名。

## 額度實際換到了哪些素材？

除了程式，我也用既有訂閱完成文章的配套素材。

| 資源 | 完成內容 | 可核對的實扣 |
|---|---|---|
| Suno v6 | 木琴冒險、電子節奏、室內樂返航，三種風格各兩首 | 30 credits |
| ElevenLabs Multilingual v2 | 約 75.6 秒繁中介紹旁白 | 383 credits |
| 四個編碼模型 | 四份遊戲、檢查與修正紀錄 | 扣點資料不完整，暫不填總成本 |

六首配樂都是候選，還沒有選定正式用曲；既有旁白和影片初剪仍是三版內容，加入第四版後需要更新。四份遊戲維持無聲，讓第一輪試玩先集中在操作。

## 接下來，讓玩家用成品投票

背景瀏覽器已操作開始、暫停、版本切換與揭曉；GPT-6 Astra 版也實際完成接人返港、時間耗盡與重玩。真正手機的觸控手感與真人難度，仍需要另外驗收。

正式投票會要求每版實際玩滿 15 秒，再選一個喜歡的版本，揭曉時顯示各版票數、比例與總樣本。每個匿名瀏覽器每期一票，但換裝置仍可能重投，因此結果會標示為自願參與者的偏好。
