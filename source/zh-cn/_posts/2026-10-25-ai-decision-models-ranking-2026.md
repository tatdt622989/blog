模型越大，决策质量就越好吗？最便宜的 API 真的是总体成本最低的吗？本文根据真实场景比较 16 个选项，严格区分模型、供应商、接入渠道和待验证数据。

本文的“排名”代表**按场景推荐的测试优先级**，不是声称已完成全部模型的统一跑分。新产品如无可核对的长期官方定价，就不编造数字。

## 一眼選型：先看任務，而不是廣告排名

| 需求 | 先評估 | 為什麼 |
| --- | --- | --- |
| 單題多選一、偏好排序 | GLiDE、Decider、Elephant | 用一致題集比较决策正確率與速度 |
| 高风险多條件權衡 | Mammoth、d1-ultra、通用推理模型 | 看校準、棄答和錯誤代價 |
| 工作流程及 Agent | Jev、System One、Claude、GPT | 工具呼叫成功率比單次答題分數重要 |
| 有歷史標籤的數值／交易訊號 | LightGBM、XGBoost，加 LLM 解釋層 | 不要用文本能力替代時序回測 |
| 私有数据、自架與離線 | Qwen、Laya（先查授權）、传统 ML | 帳單以 GPU、維護與吞吐計算 |

## 編輯選型排行：按用途，不假裝有跨榜單第一名

**推薦优先實測順序（不是 benchmark 得分排序）：**

1. **結構化單題决策：** GLiDE v1.2、Decider V1.2、Elephant-1。先用相同输入、格式验证與成本量測挑出前兩名。
2. **複雜多因素判斷：** Mammoth-1、d1-ultra，以及 Claude/GPT 這類通用推理對照組。此類工作不能只看决策百分比。
3. **代理流程决策：** Jev、System One 路由，以及支援工具調用的通用模型。测试必須包含錯誤恢復、工具选择與重試成本。
4. **自架／預測：** 若有歷史標籤與數值特徵，先拿 LightGBM / XGBoost 當基準；Qwen 或可合法部署的决策模型作補充。

排名只是**選型與测试优先度**，不是已完成同條件跑分的客觀排行榜。沒有公開一致测试的方案，一律不宣稱準確率領先。

## 如何自己建立可信的决策模型排行榜

每個模型使用**相同的 200～1000 道保留测试題**，分成有标准答案的知識决策、风险與收益權衡、動態情境及拒答／数据不足四組。保持相同提示、選項順序隨機化、溫度（可用時）、输出 schema 與重試預算。至少重複三次，報告平均值與波動。

| 指標 | 計算／解釋 | 最常被忽略的陷阱 |
| --- | --- | --- |
| 决策正確率 | 正確數 / 有標籤題數 | 不同難度題庫不可直接比 |
| 選項偏誤 | 交換 A/B 順序後有多少翻盤 | 模型可能偏好位置而非答案 |
| Calibration / Brier score | 概率預測與結果偏差，越低越好 | 文字寫「90% 信心」不等於校準 |
| 棄答品質 | 数据不足時是否要求補充数据 | 只獎勵強制回答會鼓勵胡猜 |
| P50/P95 延迟 | 真正 API 請求端到端耗時 | 首 token 與完整输出不是同一指標 |
| 有效决策成本 | （總付費含重試）/ 合格結果數 | 單純比每百萬 token 會失真 |
| 穩定性 | 成功率、429 比例、區域可用性 | 試用額度期間的數字不代表長期 SLA |

對時間序列、投資和交易任務，務必**按時間切分訓練與测试数据**，避免未來資訊洩漏。LLM 的語言流暢度不代表有超額收益；請記錄基準策略、手續費、滑價、回撤、樣本外結果與概率校準，不可僅看單筆命中率。

## 价格到底怎麼比？給你一個可重算公式

若 API 以每百萬 token 計費，單次成本為：

`cost = input_tokens / 1_000_000 * input_price + output_tokens / 1_000_000 * output_price`

例如**假設價**输入 $0.30、输出 $1.20（這是算例，不代表表內任何真實型號），每次 2,000 input + 250 output tokens：成本為 **$0.0009**；執行 100,000 次則為 **$90**，尚未加上失敗重試、搜尋、工具與快取費用。同一產品若使用每次呼叫、每題或訂閱制，就應換算成「一萬次有效决策成本」，不能強行填入 token 單價。

## 最後建議

**不要為了追逐某個榜單的第一名就更換整套系統。** 先選 2～3 個候選者跑自己任務的保留测试集，逐項記錄价格、延迟、格式通過率和錯誤代價。對商業生產决策，預留 fallback、版本固定、日志與人類審核；對不可逆或高风险動作，需明確門檻及熔斷條件。
